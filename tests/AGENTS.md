# Работа с тестами

## 1. Выбор места

Каталог задаёт область непосредственно испытываемого входа: architecture,
domain_primitives, platform, capabilities/<capability>, composition, cli,
evaluation, verification или tooling. CLI остаётся в cli независимо от глубины
вызовов; прямой runtime — composition; прямой broker/ledger — platform.
Helpers подготовки и транзитивные вызовы категорию не меняют.

Без вызова классифицируй поверхность: форма компонента — у компонента,
архитектурный контракт нескольких областей — architecture. Мутанты, испытывающие
сам верификатор, — verification; применение проверки к настоящему дереву ради
контроля архитектуры — architecture. Независимые сценарии разных входов разделяй.
Единый совместный сценарий без одного компонентного входа — composition.
Не создавай milestone-каталоги rN или сборные misc/integration/contracts.

Гейт: `.harness/scripts/checks/tests_layout.py` проверяет полный index перед
коммитом; вручную: `python3 .harness/scripts/checks/tests_layout.py --worktree`.
Он проверяет корневые категории и типы записей, включая запрет symlink/gitlink.
`[без гейта]` Смысл классификации и вложенные milestone-каталоги проверяет ревью.

## 2. Файлы и помощники

Тестовые модули — test_<предмет>.py; функции называют наблюдаемое поведение.
R-версия допустима, если различает контракт или эталон совместимости.
Не импортируй test-модули. Общие builders — tests/support; локальные — support.py
либо support/ области. Fixtures — ближайший conftest.py нужной области видимости.
Не выноси helper общего назначения без нескольких потребителей.

`[без гейта]` Область fixtures, уместность helpers и отсутствие импортов тестов
проверяются ревью; importlib-mode и статическая типизация проверяют загрузку.

## 3. Изменение набора

При переносе обнови selectors в verification/runner.py и r1_lane.py, исполняемые
successor_evidence в architecture/r7_compatibility.py и импорты/ресурсные пути.
Исторические predecessor IDs не переименовывай как текущие пути.
При изменении этих исходников пересмотри boundary evidence перед актуализацией
inert_shared/r8-implementation-v1.json; пересчёт хешей сам по себе не является ревью.

Сохрани отображение старых nodeids в новые с параметрами и результатами
setup/call/teardown, skip/xfail. Разделённые проверки наследуют прежние evidence-срезы.
Удаление или замена требует объяснения утраченного контракта либо актуального
преемника с наблюдаемым покрытием. Один R-префикс не обосновывает удаление.
Выполни pytest, lint/type checks и затронутые verification lanes; implementation
PASS не означает разрешённый deployment.

`[без гейта]` Полнота переноса смысла требует сравнения и ревью, а не равенства
количества тестов. pytest и гейт подтверждают только проверяемые ими исходы.
