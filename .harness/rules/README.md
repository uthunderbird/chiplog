# Правила

Каждое правило родилось из провала и имеет тест-репродьюсер — заведомо плохой вход,
который оно когда-то поймало. Правило без репродьюсера гейт не пропустит.

Исключение — норма, установленная человеком словом (`norm: true`). Она легальна,
но ходит под кадансной ревизией, пока не обрастёт входом.

Заводить: `./.harness/scripts/new-rule.sh "что сломалось"`

## Обратный ход

Правила только прибавляются — это храповик, и через год он превращает харнесс
в тот самый чёрный ящик, против которого весь метод. Поэтому удаление —
процедура, а не вкусовщина:

1. удали правило;
2. прогони его репродьюсер;
3. гейт всё равно ловит — правило было мёртвым весом, удаляй;
4. ошибка рецидивирует — правило несущее, верни.

Решает воспроизводимый прогон, не память.

## Границы

Репродьюсер — критерий необходимый, не достаточный. Стохастичный провал требует
серии прогонов, а правило бывает шире своего входа: репродьюсер ловит один случай,
правило охраняет класс. Отсюда отдельный контур — ред-тим на самом харнессе,
ищущий коллизии между правилами, которых ни один репродьюсер не видит.
