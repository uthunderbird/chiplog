## Классы, а не случаи

**Повторяющийся продуктовый класс: номинальное согласие вместо замкнутого стыка.** В копилке это source accounting/binding, native-shaped writer mismatch, SUSP representations, recovery provenance и readiness consumer seams. В текущем периоде тот же механизм виден в private connection escape и ledger object-model replacement: знакомое имя receiver/SQL не удостоверяет, что выбранная actual capability дошла до consumer. Связанный риск engine evidence — ожидания, выведенные из самой candidate SQL/schema, совпадут с ошибкой candidate. Локальный ответ: исходный corpus node и source digests, exact origin/forward/sink, независимые fixed SQL/DDL/action expectations, physical metadata на той же disposable connection, canonical rederivation против mutually forged DTO. Это шире одного файла и применимо к другому producer/consumer стыку.

**Что решено хорошо.** `authority_descriptor_closure.py` сохраняет каждый call/reference и unresolved остаток; known chains остаются `CONDITIONAL_LOCAL`. `selected_engine_contracts.py` не импортирует candidate schema для вычисления ожиданий; `selected_engine_evidence.py` сравнивает фактическое memory-наблюдение, отдельно хранит business/catalog/metadata dependencies. EMPTY/EXISTING ledger cases различают первый CREATE и `IF NOT EXISTS` no-op. `require_closed()` глобального inspection и fragment безусловно отказывает, даже при подделанном пустом unknown inventory. Закрепление здесь уже есть в source/tests и действующих §6/§11; ещё одна процессная норма не нужна без собственного входа.

**Не получилось с первого раза.** Status периода фиксирует 19 initial preparation RED и дополнительные escape/default cases; ledger hook-family RED, шесть structural guards с последующим controlled guard-removal, затем три ImportFrom alias RED. Не смешивать эти истории в «все тесты были RED-first». Exact serializer counts дали локальные RED для двух последовательных мест; это продуктовый класс повторной работы над тем же immutable operand. Положительный/отрицательный tests прочитаны, но здесь не перезапущены.

**Не объединять в класс инструкции.** Ошибочный setup symbol, dict-as-attribute, неверная цель reviewer и одиночный source drift — отдельные эпизоды из копилки. Для них уже применимы §§1/4/6/9; история не устанавливает недостающую норму. В текущем периоде есть продуктовые mutants, а faithful standalone agent-case и old/new replay не создавались. Ретро не утверждает ни эффективность новой инструкции, ни невозможность такого входа.

**Граница пользовательского исхода.** Selected schema/engine comparisons — prerequisite evidence, а не admitted live schema, shipment/engine artifact, WAL/locks, default FK, closed receiver graph, registered descriptor/CURRENT либо mandatory startup admission. `build_planning_descriptor_fragment` перечисляет их в residual obligations. Связь proof до public startup consumer всё ещё обязательна; helper PASS не закрывает handoff работы и весь R14. Frozen run10005 не трогался, результата за него эта ретро не присваивает.
