## Пять линз

### 1. Что решено хорошо и стоит закрепить

Contract freeze разделил R1-owned, R2-owned и integration-owned поверхности до независимой
реализации. A97 был принят fail-closed: exact-set остановил устаревший канон, после чего
registry и тесты обновились отдельным rebase. Git-env проблема закрыта на уровне класса:
wrapper очищает полный список `git rev-parse --local-env-vars`, а интеграционный тест
проверяет наблюдаемый исход — сохранность owner HEAD/index/config и независимый nested commit.
Lane verifier не активирует `stage0`, поэтому локальная зелень не выдана за интеграционный claim.

Дополнительно закрепить нужно только collision-safe создание ретро: для него есть
детерминированный плохой вход. Contract freeze пока остаётся удачным локальным паттерном,
а не новым обязательным правилом.

### 2. Что не получилось с первого раза

Repository-creating test унаследовал Git-local scope hook и мог мутировать owner repository:
gate раньше не задавал process boundary для таких адаптеров. Это уже закрыто общим wrapper и
репродьюсером. Изменение canonical input потребовало A97 rebase, но здесь существующий
exact-set сработал штатно. Подтверждённая незакрытая ошибка: identity записи ретро равна
календарной дате, хотя `AGENTS.md §8` допускает несколько incident/cadence событий за день.

Конкретная порча старого worktree, clean re-materialization и состав cold P1 известны из
процессного контекста, но не подтверждены отдельным durable trace этой ветки; превращать их
в правила без agent-case нельзя.

### 3. Что из прежнего харнесса работает и что улучшить

Работают exact inventory, fail-closed gate, lane verifier, cold isolation, contract freeze,
общая очистка Git-local environment и paired self-test. Улучшить нужно allocator ретро:
явный qualifier, закрытая валидация, атомарная публикация без overwrite и actionable failure.
`retro_due.py` должен учитывать несколько валидных записей за дату в порядке их добавляющих
Git-коммитов, а не в лексическом порядке qualifier.

### 4. Где была фрикция

Таблица выше разделяет устранимый выбор пути и неизбежную цену правильного fail-closed rebase.
Ручное именование второй ретро не является нормой: разрешённому workflow нужен штатный путь.

### 5. Какой harness change предлагается

Добавить `new-retro.sh --id <safe-id>`: default сохраняет `YYYY-MM-DD.md`, явный id создаёт
`YYYY-MM-DD-<id>.md`; id принимается только закрытым regexp; fully rendered tempfile
публикуется атомарным hard-link; существующий target не меняется. Collision сообщает
`→ сделай:` с двумя ветками: открыть существующую запись, если это та же ретро, либо повторить
с явным `--id`. Тест фиксирует base digest, создаёт id, повторяет его и проверяет nonzero
и неизменность bytes. Отдельный тест создаёт same-date записи в порядке, противоположном
лексическому, и проверяет skip streak по Git history.

## Классы, а не случаи

### C1 — allocator артефакта предполагает уникальность календарной даты

Initializer использует дату как единственную identity, хотя независимые worktrees или
incident/cadence runs законно создают несколько однотипных артефактов в день. Дешёвые
обходы — overwrite, ручное невалидированное имя либо потеря второго следа. Текущий
исполняемый вход: повторный `new-retro.sh` при существующем дневном файле. Исправление
остаётся узким: явная дополнительная identity только при collision, без угадывания имени.

### O1 — supplied worktree corruption не имеет agent-case triple

Старый worktree и clean re-materialization описаны процессным контекстом; код и тест
показывают достижимость Git-env corruption, но не являются независимым журналом исходного
инцидента. Находка ждёт родню в копилке и не получает правило в этой ретро.

## Кандидаты в правила

Принять tool repair в `.harness/scripts/new-retro.sh` с executable integration test:

- explicit `--id`, а не автоматический `-02`, который два worktree выберут одинаково;
- safe closed alphabet и запрет path separators;
- atomic publish и сохранение bytes существующих файлов;
- actionable collision с владельцем следующего действия;
- multiple same-date entries упорядочиваются `retro_due.py` по добавляющим Git-коммитам.
