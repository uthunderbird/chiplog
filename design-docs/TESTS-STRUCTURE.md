# Структура тестов Chiplog

База миграции — R8 `1d5578a940b30911433b6483ba12356929b54084`.
Перед merge включён параллельный harness-коммит `c324672`; его новые preflight
и post-tool тесты перенесены в tooling, ссылки и порядок dispatcher обновлены.
Действующие инструкции находятся в `tests/AGENTS.md`; карта прежних функций,
семантических замен, параметризаций и результатов — в `quality/test-migration.json`.
Документ описывает принятое устройство и границы его проверки.

## Размещение

Первый уровень задаёт область непосредственно испытываемого входа:

| Каталог | Испытываемый вход |
|---|---|
| `architecture` | Настоящие manifests, inventory и ограничения связей |
| `domain_primitives` | Канонизация и базовые значения |
| `platform` | Storage, ledger, broker и механизмы чтения/допуска |
| `capabilities/<capability>` | Публичные и внутренние контракты capability |
| `composition` | Собранный runtime, процессы, restart, совместные сценарии |
| `cli` | Настоящий пользовательский CLI |
| `evaluation` | Компилятор транскриптов и evaluation infrastructure |
| `verification` | Алгоритмы верификатора, проверяемые мутантами |
| `tooling` | Харнесс, hooks, packaging, quality checks |
| `support` | Общие явно импортируемые builders |

Это локальный выбор проекта, а не универсальная классификация pytest.
Helpers подготовки данных и транзитивные вызовы не меняют категорию. Прямой
runtime.render относится к composition даже при surface_id `cli.render`.
Проверка формы DTO относится к его области; межкомпонентный freeze — architecture.
Применение verifier к настоящему inventory проверяет архитектуру; мутация inventory
для испытания алгоритма verifier относится к verification.

Смешанные файлы разделены по сценариям. В смешанном контракте graph/port
структурная проверка broker protocol выделена отдельно от composition graph.
Имена R7/R8 сохранены только для версий контрактов и эталонов совместимости;
каталоги milestones, integration, contracts и conformance удалены из tracked дерева.
Общие helpers вынесены в support, импорты соседних test-модулей устранены.

## Замена исторического R6

CLI-тесты с подстановкой старого runtime и тесты устаревших in-process bridges
заменены сценариями текущих входов. Persist/replay/restart/render проверяются через
канонический R8 runtime с независимым подписанным entitlement; отрицательные
identity, command и publication-cut сценарии наблюдают отсутствие записи.
Повреждённая запись проверяется через настоящий R8 CLI, без подмены его runtime.
Точные trust bindings проверяются на действующей deployment_trust capability,
а operation/subject — также на planning boundary.

Это семантические замены, а не заявление о равенстве старых и новых функций.
Исторический порядок вызовов R6 не сохраняется как контракт. Каждая удалённая
функция перечислена с преемниками в `semantic_replacements` карты миграции.
Реальный R6/R7 byte-parity corpus сохранён: R6 здесь остаётся историческим оракулом,
который нужен действующему compatibility ledger. Один возраст теста не служил
основанием удаления.

## Evidence и проверка переноса

Selectors R1–R8 в runner и отдельный r1_lane обновлены. Широкие каталоги заменены
явными файлами, чтобы перенос R8 в platform/architecture/capabilities не расширял
прежние evidence-срезы случайно. R6 перечисляет конкретных современных преемников;
R4 и R8 намеренно включают дополнительные текущие сценарии. Точные различия
срезов записаны в `validation.lanes` карты.

Исполняемые successor_evidence в r7_compatibility указывают на новые адреса;
исторические predecessor IDs сохранены. После просмотра diff selectors,
evidence-ссылок и комментария обновлён R8 implementation identity catalog.
Production runtime и deployment policy миграция не меняет. Stage0 implementation
PASS по-прежнему не означает разрешения deployment.

Baseline снят на точной базе R8. Pytest observer сохраняет collected nodeids и
setup/call/teardown, включая skip/xfail. Для обычных переносов сохранены параметры
и сравниваются результаты фаз; для разделений проверяются все преемники; для
семантических замен отдельно наблюдается исполнение новых сценариев. Сводка,
параметры и команды находятся в `validation` карты. Равенство количества тестов
не используется как доказательство сохранения смысла.

## Что держит гейт

`python3 .harness/scripts/checks/tests_layout.py --index` читает весь Git index,
включая неизменённые файлы. В корне tests допустимы обычные AGENTS.md, conftest.py
и __init__.py; остальные записи должны лежать под согласованными категориями.
Symlinks и gitlinks запрещены во всём тестовом дереве. Отсутствующий или нечитаемый
снимок и неразрешённый index возвращают ошибку. `--worktree` диагностирует реальные
tracked/unignored untracked файлы с учётом удаления и типов; ignored caches не входят.
Это проверка выбранного снимка, а не защита от одновременной внешней записи.

Гейт не распознаёт смысл assertions, названия функций, вложенные milestone-каталоги
или уместность fixtures. Эти свойства остаются предметом ревью. Он также не требует
пустых каталогов и не объявляет любую разрешённую папку семантически правильной.

Парные Git-фикстуры находятся в `tests/tooling/test_tests_layout.py`: неверный корень,
частичный staging, старое нарушение вне текущего diff, удаления, type substitution,
отсутствие снимка и реальный путь hook → gate с изолированными прочими проверками.
Они запускаются в pytest, gate self-test и reproducer tests-layout. Полный gate
дополнительно выполняет lint/types, fast verification, pytest и все репродьюсеры.

## Восстановление

Миграция поставляется отдельным коммитом поверх R8. При обнаружении регрессии
откатить этот коммит целиком, включая selectors, ledger и identity catalog;
частичный откат одних тестовых путей разрывает evidence. Незакоммиченную работу
основного дерева сохранить отдельно перед merge и восстановить после него.
