# R14.2: selected semantic reduction

## Status

Open. The selected original-call resolver currently publishes a basis, closure,
recovered outcome, and resolver batch. Continuation correctly holds because no
current loop-owned semantic reduction is selected. The wire DTO and record
validator exist, but there is no mounted owner preparation, writer route, or
historical selector for `chiplog.loop.semantic-reduction.v1`.

## Boundary

The resolver batch and semantic reduction are separate publications. The resolver
selects closure, recovered outcome, and resolver batch together. The reduction is
an appendable stream with its own predecessor CAS; later compatible evidence must
advance the current reduction while preserving `reduction_id`, semantic class,
and consumability. A rival or contradictory refinement must select a typed HOLD
head, so an older consumable head cannot remain current.

The selected R16 witness for a refinement can be a late `APPEND_EVIDENCE` record
whose obligation remains `CLOSED`. R14 accepts it only when the current outcome
record is selected from an authenticated full R16 chain, its command appends the
exact final evidence item after the complete prior evidence list, and the
original resolver's nonempty closure evidence remains a strict prefix. A neutral
receipt can refine provenance without duplicating child coverage; a duplicate
positive classification or rival negative evidence must not remain consumable.

`Absent` is valid only after the broker has authenticated and completely
enumerated both selected loop decisions and physical loop reduction rows for the
tenant and stream. A hard-coded empty tuple or the Effects reader's closed schema
set does not prove absence from the loop-owned stream.

## Implementation slices

1. Add owner preparation and a versioned R7 route for `PrepareLoopSemanticReduction`.
   It validates the fixed reducer policy, registered resolver authority, exact
   selected resolver anchors, complete ordered evidence, and either authenticated
   `Absent` or the selected current predecessor. It returns a proposal only.
2. Add broker publication with an independent predecessor CAS. Revalidate the
   complete evidence and anchor cut at writer admission, select one physical
   reduction record, and make replay return the exact selected bytes.
3. Extend the closed physical schema registry and historical loop reader. The
   reader must compare selected decisions, publication envelopes, and physical
   SQL rows, rejecting partial, duplicate, orphan, unknown, or competing entries.
4. Mount the current-reduction reader in the recovery consumer. It supplies only
   the latest selected reduction for the exact obligation; a prior head cannot
   satisfy continuation after refinement.

## Required mounted evidence

- First reduction from a completely enumerated `Absent` stream; exact selected
  bytes and source references survive close/reopen and idempotent replay.
- Compatible evidence refinement selects the exact next predecessor and keeps
  the same reduction identity, semantic class, and consumable disposition.
- After reopen, the refined record is current and the old head fails the consumer
  join.
- Rival or contradictory evidence selects a typed HOLD reduction; the previous
  consumable record cannot authorize continuation.
- Missing, duplicate, reordered, foreign, partial, or orphan evidence and
  reduction rows fail closed without selecting a successor or issuing another
  SEND.

These checks use the mounted writer and reader with bounded fixtures. Load,
stress, and broad combinatorial tests remain deferred to final integration under
the user's 2026-09-28 instruction.

## Scope guard

This slice ends when R14 reads and enforces the current semantic reduction after
reopen. Publishing a successor Turn after recovery is R14.3 and remains separate.
No R15–R17 implementation is part of this slice.
